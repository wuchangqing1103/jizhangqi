# 记账器 · 产品设计文档（MVP v0.1）

> 状态：草案 · 2026-11-07
> 定位：一页纸方向 + MVP 范围。细节（视觉稿、字段校验等）留到开发阶段再补。

## 1. 一句话

给自己用的轻量记账工具：**打开就能记，一个月后能看出钱花在哪。**

## 2. 目标与非目标

MVP 只验证一件事：**我能不能连续记满 7 天。**

具体到可观察的指标：

- 从打开到保存一笔 ≤ 5 秒；
- 记满 7 天后，月度统计能回答「这个月的钱主要花在哪」。

非目标：不做通用记账 SaaS、不做多人共享、不做多账本、不做财务分析报告。

## 3. 核心判断

1. 记账类产品不是死于功能少，是死于**「记一笔太麻烦」**。
2. 第二死因是**「记了没用」**——数据不给反馈，三天就弃用。

所以 MVP 的每个功能只用一个标准衡量：**要么缩短记账路径，要么让数据产生反馈。** 两条都不满足的，这一版一律不做。

## 4. 用户与场景

单用户（本人），**手机为主、电脑为辅**。

| 场景 | 占比 | 描述 | 对设计的要求 |
| --- | --- | --- | --- |
| A 付完就记 | ~70% | 便利店 12.5 元，站着就把账记了 | 全程单手，不用打字，5 秒完成 |
| B 晚上补记 | ~25% | 想起白天几笔，改日期补录 | 日期可改，且改完不会「记了看不见」 |
| C 月底回看 | ~5% | 看分类占比，判断哪类超支 | 统计页一屏说清，不点第二下 |

## 5. MVP 功能范围（P0）

| 模块 | 功能点 | 说明 |
| --- | --- | --- |
| 记一笔 | 金额、支出/收入、分类、日期、备注（选填） | 底部面板 + 自建数字键盘；默认支出、默认今天、进来即可输金额 |
| 账单流 | 按月浏览、按日分组带日小计 | 顶部是当月支出大数字 + 收入/结余；点条目进编辑 |
| 月度统计 | 支出/收入切换、分类占比条形图 | 显示金额 + 百分比，按金额从大到小 |
| 编辑与删除 | 复用记账面板改内容 | 删除需二次确认 |
| 数据持久化 | 浏览器本地存储 | 无需登录、无需联网，打开即用 |

这五项之外，MVP 不加任何东西。

## 6. 交互约定：「3 秒记一笔」

标准路径，共 4 步：

```
打开 → 点「+」→ 输 12.5 → 点「餐饮」→ 保存
```

默认值把所有必填项都填好，用户实际只需做两个决定：**多少钱、哪一类**。

配套规则：

- 金额单位元、最多两位小数；整数金额省略 `.00`（显示 12 而不是 12.00）；
- 分类用「图标 + 文字」的九宫格，不用下拉框；
- 同一天多条按创建时间倒序，最新在最上；
- 记到非当前月份时，自动跳转到该月，避免「记了看不见」；
- 键盘输入与系统键盘不抢焦点，金额框不需要点。

## 7. 明确不做（及原因）

| 功能 | 现在不做的原因 | 计划 |
| --- | --- | --- |
| 登录 / 云同步 | 引入账号体系，MVP 阶段零收益 | v2 |
| 多账本 / 多账户 | 增加「这笔记哪个账本」的选择成本 | v1.2 |
| 预算与超支提醒 | 要先有一个月历史数据才有意义 | v1.1 |
| 周期账单（房租、订阅） | 频率低，手记一次即可 | v1.2 |
| 图表美化、动画 | 不影响留存 | 长期低优先 |
| 拍照 OCR、语音记账 | 识别错误后的纠错成本比手记更高 | v2 |
| CSV 导入导出 | MVP 没有历史数据可导 | v1.1（同时作为备份手段） |
| 多币种 | 单币种场景够用 | 不做 |
| 标签体系 | 与分类功能重叠，先观察是否真需要 | v1.2 |
| 多人共享 | 是另一个产品 | 不做 |

## 8. 信息架构（三个界面）

1. **账单页**（默认）：月份切换 → 汇总卡 → 按日分组的流水 → 底部「+」。
2. **统计页**：支出/收入切换 → 总额 → 分类条形排行。
3. **记账面板**（浮层）：类型切换、日期、金额、分类九宫格、备注、数字键盘、保存（编辑时多一个删除）。

页面之间只有一层：账单 ⇄ 统计，记账面板随时从底部弹出。

## 9. 数据模型

```
RecordItem {
  id        string   唯一标识
  type      'expense' | 'income'
  amount    number   金额，单位「分」，整数（规避浮点误差）
  category  string   分类 id
  date      string   YYYY-MM-DD，本地时区
  note      string   备注，可为空
  createdAt number   创建时间戳，同日排序用
}
```

存储：一个本地 key 保存 `{ version, records: [] }`，`version` 留给以后做数据迁移。读取时任何异常（无数据、JSON 损坏、字段不符）都退化成空账本，**不弹错、不白屏**。

## 10. 分类

- 支出 9 类：餐饮、交通、购物、居住、娱乐、医疗、学习、人情、其他
- 收入 5 类：工资、奖金、理财、兼职、其他

规则：MVP 固定不可编辑；切换支出/收入时，若当前分类不属于新类型，自动落到新类型的首项/「其他」。

## 11. 成功标准（MVP 算「做完」的判定）

- [ ] 真机实测：打开到保存一笔 ≤ 5 秒
- [ ] 连续 7 天真实使用，中途没有想放弃
- [ ] 刷新、关页面、重启浏览器后数据不丢
- [ ] 手机浏览器可用，能添加到主屏当 App 用
- [ ] 统计页一眼看出前三大支出分类
- [ ] 记错能改、能删

## 12. 后续路线

| 版本 | 内容 | 触发条件 |
| --- | --- | --- |
| v1.1 | CSV 导出/导入（先做导出）、预算 | 连续记满 7 天 |
| v1.2 | 自定义分类、多账本、周期账单 | 有真实痛点再说 |
| v2 | 云同步、多端、拍照记账 | 换手机或想在电脑上记 |

## 13. 风险与取舍

- **数据只在本机**：清缓存、换设备即丢失。v1.1 用导出兜底；在那之前明确接受这个代价。
- **不做登录**：省掉整套账号体系，代价是无法多端。可接受。
- **分类固定**：先观察一个月真实使用，再定自定义分类的形态，避免过早设计。
- **只有按月视图**：没有「全部账单」入口，看历史要翻月份。MVP 够用。
